# プラグインの使い方（利用者向け）

<!-- vea-tab-help: plugins -->

vCenter Event Assistant は、vCenter からデータを取り込む処理を **コレクタ** という単位に分けて持っています。標準で付いてくる **組み込みコレクタ**（イベント収集、ホストの統計、データストア容量など）に加えて、**外部プラグイン**を追加すれば取り込める情報を増やせます。プラグインの構成と動作状況は **設定 → プラグイン** で確認します。本書は開発者向けではなく、プラグインを導入・有効化し、動いているか確認し、失敗したときに切り分けたい運用担当者向けに、現行の挙動をまとめたものです。

---

| あなたの役割 | まず読む節 | 目的 |
|-------------|-----------|------|
| **運用（確認）** — いま何が動いているか見たい | [§4](#4-画面の見方) | 一覧と実行状況の読み方 |
| **運用（把握）** — 標準で何を集めているのか知りたい | [§2.1](#21-標準で付いてくるコレクタ) | 同梱コレクタの一覧と役割 |
| **運用（導入）** — プラグインを入れて有効にしたい | [§3](#3-二つのモード参照専用と管理有効) → [§5](#5-使い始める手順管理機能が有効な場合) | 導入から反映までの手順 |
| **運用（調査）** — データが来ない／エラーが出る | [§8](#8-うまく動かないときの切り分け) → [§9](#9-よくある質問) | 原因の絞り込み |
| **サーバー管理者** — 有効化してよいか判断したい | [§7](#7-安全に関する注意) → [backend-operations.md](../backend-operations.md) | リスクと前提条件 |
| **自分でプラグインを作りたい** | [collector-plugin-authoring.md](../collector-plugin-authoring.md) | 本書の対象外 |

用語が似ているので、次の区別をしてください。

| 用語 | 意味 |
|------|------|
| **コレクタ** | データを取り込む処理の単位。画面の一覧に 1 行ずつ並ぶもの。 |
| **プラグイン ID** | コレクタの識別子（例: `builtin.vcenter.events`、`example.host.temperature`）。設定ファイルや環境変数ではこの ID を指定する。 |
| **配布物（ディストリビューション）** | インストールする Python パッケージそのもの（`.whl` / `.tar.gz`）。1 つの配布物が複数のコレクタを提供することがある。**インストール済みプラグイン**の表に並ぶのはこちら。 |
| **組み込み / 外部** | 一覧の **提供元** 列。**組み込み**はアプリに同梱され既定で有効。**外部**は追加インストールしたもので、明示的に有効化するまで動かない。 |
| **レジストリ世代** | 現在稼働している構成の版数。**変更を反映**を押すたびに 1 つ増える。増えていれば新しい設定が適用されている。 |

## 2. プラグインでできること

コレクタが取り込んだデータは、そのまま既存の画面に流れ込みます。

| プラグインが返すもの | 保存先 | どの画面に出るか |
|---|---|---|
| **イベント** | イベントテーブル | **イベント** タブの一覧、**概要**、要注目スコアの採点対象、ダイジェストやチャットの調査対象 |
| **メトリクス** | メトリクステーブル | **グラフ** タブの時系列、メトリクス閾値型のアラートルールの評価対象 |

つまり、外部プラグインを追加すると「vCenter の標準イベント以外のできごと」や「vCenter が標準では出さない数値」を、既存の一覧・グラフ・スコア・アラートの仕組みにそのまま載せられます。プラグイン側で画面が増えるわけではありません。

一覧の **データ種別** 列が、そのコレクタの返すものを示します（**イベント** / **メトリクス** / 両方）。

### 2.1 標準で付いてくるコレクタ

アプリには次の 4 つの**組み込みコレクタ**が同梱されており、既定ですべて有効です。それぞれが何を集めているかは、画面で行を開いたときの説明にも同じ内容が出ます。

| プラグイン ID | 集めるもの | 出る場所 | 無効にすると |
|---|---|---|---|
| `builtin.vcenter.events` | vCenter のイベント（タスク・アラーム・ログインなど）を、前回の続きから取得する | **イベント**タブ、**概要**、要注目スコア、アラート、ダイジェスト、チャット | イベント側の情報がすべて更新されなくなる。通常は有効のままにする |
| `builtin.vcenter.host_quickstats` | ESXi ホストの **CPU 利用率**と**メモリ利用率**（`quickStats` 由来。負荷の軽い呼び出し） | **グラフ**タブ、**概要**ダッシュボード、メトリクス閾値のアラート | ホストの CPU / メモリの推移が途切れる |
| `builtin.vcenter.host_performance` | ESXi ホストの**ネットワーク**（送受信エラー・破棄・スループット）と**ディスク**（使用率・読み書き） | **グラフ**タブ、メトリクス閾値のアラート | ネットワーク・ディスク系の指標が途切れる。CPU / メモリは残る |
| `builtin.vcenter.datastore_capacity` | データストアの**使用容量**（使用率 % と使用バイト数） | **グラフ**タブ、メトリクス閾値のアラート | 空き容量の推移と、それを見るアラートが更新されなくなる |

メトリクス系の 3 つは、集める対象が重ならないように分かれています。**実行間隔を個別に変えたい**（容量は 30 分ごとで十分、CPU は 5 分ごと）、**片方だけ失敗している**のを切り分けたい、といった運用ができるようにするためです。

リポジトリの [`examples/`](../../examples/) には、外部プラグインの書き方を示す**サンプル**が 2 つ入っています（ホスト温度のメトリクス、仮想マシンの電源イベント）。どちらも動作確認と雛形のためのもので、実際のセンサーを読んだり運用に使ったりするものではありません。既定ではインストールされていません。

## 3. 二つのモード（参照専用と管理有効）

**この画面でできることは、サーバー側の設定 `VEA_PLUGIN_MANAGEMENT_ENABLED` によって変わります。** 最初にどちらのモードかを確認してください。画面上部の説明文で見分けられます。

| | **参照専用**（既定） | **管理有効**（`VEA_PLUGIN_MANAGEMENT_ENABLED=true`） |
|---|---|---|
| 構成と実行状況の閲覧 | できる | できる |
| 有効／無効の切り替え、実行間隔・タイムアウトの変更 | できない | 画面からできる |
| パッケージのインストール／アンインストール | できない | 画面からできる |
| 設定の変更方法 | TOML ファイル（`VEA_COLLECTOR_CONFIG_FILE`）または環境変数 | 画面のフォーム（TOML・環境変数も引き続き有効） |
| 変更の反映方法 | **アプリの再起動** | **変更を反映**ボタン（再起動不要） |

参照専用のまま運用するのが既定であり、推奨でもあります。管理を有効にするかどうかは [§7](#7-安全に関する注意) を読んでサーバー管理者が判断してください。

## 4. 画面の見方

### 4.1 一覧

| 列 | 意味 |
|---|---|
| **プラグイン** | 表示名とプラグイン ID。左の **▸** を押すと詳細行が開く。 |
| **状態** | **有効** … 稼働中。**無効** … 登録されているが動かない。**エラー** … 構成の読み込みに失敗しており動かない。 |
| **データ種別** | **イベント** / **メトリクス**（両方返すものは併記）。 |
| **提供元** | **組み込み** / **外部** / **設定のみ** / **検出**。**設定のみ**は、設定ファイルに書かれているのに対応する配布物が見つからない状態を指す（[§8](#8-うまく動かないときの切り分け) 参照）。 |
| **バージョン** | プラグインが宣言しているバージョン。 |
| **実行間隔** | 何秒ごとに実行するか。 |

一覧の見出し横には **レジストリ世代** と、**一覧を更新**（表示の再取得のみ）、管理有効時は **変更を反映**（設定を稼働中の構成に適用）のボタンがあります。**一覧を更新と変更を反映は別物です。** 設定を保存しただけでは動作は変わりません。

未反映の変更があると、一覧の上に「未反映の変更があります。」の帯が出ます。

### 4.2 行を開いたときの詳細

- **説明** … そのコレクタが何を集めるか。プラグイン側が宣言していない場合は表示されません（組み込みの 4 つには必ず付いています）。
- **API バージョン** … そのプラグインが対応しているプラグイン API の版。アプリ側と一致しないものは読み込まれません。
- **タイムアウト** … 1 回の実行がこの秒数を超えると、そのプラグインのワーカープロセスを強制終了します。
- **登録元** … 内部的な登録経路（`builtin`、`entry_point:<配布物名>` など）。問い合わせの際に添えると原因の切り分けが早くなります。
- **構成エラー** … 設定の読み込みに失敗した理由（状態が **エラー** のときのみ）。
- **設定**（管理有効時のみ） … 有効にするチェックボックス、**実行間隔（秒）**、**タイムアウト（秒）** と **保存** ボタン。
- **vCenter 別の実行状況** … 下記。

### 4.3 vCenter 別の実行状況

コレクタは vCenter ごとに実行されるため、実行状況も vCenter ごとに並びます。

| 列 | 読み方 |
|---|---|
| **状態** | **未実行** / **実行中** / **成功** / **失敗** |
| **使用バージョン** | 直近の実行で実際に使われたプラグインのバージョン。更新したのに古い値なら、**変更を反映**がまだの可能性がある。 |
| **開始日時 / 成功日時 / 失敗日時** | 直近それぞれの時刻。**開始日時だけが進んで成功日時が止まっている**なら、実行はされているが毎回失敗している。 |
| **直近成功時の追加件数** | `イベント N / メトリクス N`。0 件が続く場合、プラグインは正常でも取得対象が無いか、絞り込み条件が厳しい可能性がある。 |
| **エラー** | 直近の失敗内容。表示が型名だけになる理由は [§8](#8-うまく動かないときの切り分け)。 |

### 4.4 インストール済みプラグイン（管理有効時のみ）

一覧の下に、動的にインストールした**配布物**の表が出ます。

| 列 | 意味 |
|---|---|
| **配布物** | パッケージ名。失敗時はエラーが下に添えられる。 |
| **バージョン** | インストールされた版。 |
| **状態** | **インストール中** / **インストール済み** / **失敗**。 |
| **取得元** | アップロードかインデックスか。 |
| **インストール日時** | 表示タイムゾーンでの時刻。 |
| （右端） | **削除**（アンインストール）。確認ダイアログが出る。 |

## 5. 使い始める手順（管理機能が有効な場合）

1. **パッケージを用意する** — プラグイン作者から `.whl` または `.tar.gz` を受け取ります。自分で作る場合は [コレクタプラグインの開発](../collector-plugin-authoring.md) を参照してください。
2. **アップロードする** — **インストール済みプラグイン**の「パッケージ（.whl / .tar.gz）を追加」からファイルを選びます。インストールには数十秒かかることがあり、状態は自動で更新されます。**インストール済み**になるまで待ってください。
   - インデックス（PyPI など）から名前で入れる欄は、サーバー側で `VEA_PLUGIN_ALLOW_INDEX_INSTALL=true` にしている場合のみ表示されます。
3. **一覧に現れたことを確認する** — 新しく入れたコレクタは **無効** の状態で一覧に並びます。エントリポイントを提供しない、あるいは読み込みに失敗したパッケージは、インストール自体が巻き戻され、一覧には現れません。
4. **有効化して設定する** — 行を開き、**設定** の「有効にする」をチェックします。必要なら **実行間隔（秒）** と **タイムアウト（秒）** を入力して **保存** を押します。
5. **変更を反映する** — **変更を反映** を押します。ここではじめて稼働中の構成に適用され、**レジストリ世代**が 1 つ増えます。**アプリの再起動は不要です。**
6. **動作を確認する** — 行を開き、**vCenter 別の実行状況** が **成功** になり、**直近成功時の追加件数** が増えることを確認します。最初の実行までは最大で実行間隔ぶんの時間がかかります。

**元に戻したいとき**は、無効化して **変更を反映**、または **削除**（アンインストール）して **変更を反映** します。外部プラグインは専用のワーカープロセスで動くため、ハングしてもタイムアウトでそのワーカーだけが停止され、アプリ本体や他のプラグインは動き続けます。

参照専用モードの場合は、上記の 4〜5 の代わりに TOML ファイルまたは環境変数を編集し、アプリを再起動します。書き方は [コレクタプラグイン（設定リファレンス）](../collector-plugins.md) を参照してください。

## 6. 設定値の決まり方（画面で変更できない項目がある理由）

チェックボックスや入力欄が灰色になり「環境変数で固定されているため、画面からは変更できません。」と出ることがあります。これは設定の**優先順位**によるものです。

| 優先 | 参照元 | 対象 |
|---|---|---|
| 1（最優先） | **環境変数** | 有効/無効、実行間隔、タイムアウト、プラグイン固有の値 |
| 2 | **画面での設定**（データベースに保存） | 有効/無効、実行間隔、タイムアウト |
| 3 | **TOML ファイル** | すべて |
| 4 | **プラグインの既定値** | 実行間隔の初期値 |

上位で指定された項目は下位を上書きします。画面から変えたい項目が固定されている場合は、サーバー側でその環境変数を外す必要があります（[backend-operations.md](../backend-operations.md) 参照）。

パスワードや API キーなどの**機密値は、プラグインが指定する専用の環境変数**に置きます。データベースにも TOML にも保存されず、画面にも一切表示されません。必要な環境変数の名前は、そのプラグインのドキュメントを確認してください。

## 7. 安全に関する注意

**プラグインは信頼された Python コードであり、アプリケーションと同じ権限で動作します。** プロセス分離はクラッシュ・ハング・依存関係の衝突を切り離すためのものであり、**悪意あるコードに対するサンドボックスではありません。** プラグインは、そのワーカーに渡された vCenter の認証情報にアクセスできます。**信頼できる提供元のパッケージだけをインストールしてください。**

管理機能（`VEA_PLUGIN_MANAGEMENT_ENABLED=true`）を有効にすると、画面からのインストールは**実質的に任意コード実行**になります。本アプリ単体は認証を行わないため、有効にしてよいのは次を満たす場合だけです。

- リバースプロキシで `/api/plugins` に認証を必須にしている
- `VEA_PLUGIN_ALLOW_INDEX_INSTALL` は原則 `false` のままにし、アップロード経路のみを使う（外部インデックスからの取得はサプライチェーンリスクを増やします）
- `VEA_PLUGIN_DIR` を永続ボリュームに割り当てている

既定ではいずれも無効です。本番環境で管理機能を有効にすると、起動時にログへ WARNING が出ます。

## 8. うまく動かないときの切り分け

### 8.1 まずどこを見るか

| 症状 | 見る場所 |
|---|---|
| 一覧に出てこない | インストール済みプラグインの表（状態が **失敗** になっていないか） |
| 状態が **エラー** | 行を開いて **構成エラー** |
| 状態は **有効** だがデータが来ない | **vCenter 別の実行状況**（**失敗** か、そもそも **未実行** か） |
| 設定したのに変わらない | **レジストリ世代**が増えているか（**変更を反映**を押したか） |

### 8.2 エラー表示が短い理由

実行状況の **エラー** 欄は、既定では**例外の型名と定型句だけ**です。例外の文言には認証情報やサーバーの応答内容が含まれうるため、そのまま画面に出していません。読み込み失敗や検証エラーなど、文言が安全だと分かっている種類に限り、メッセージも表示されます。

**完全な情報は必ずアプリのログにあります。** 外部プラグインはワーカープロセスで動き、その出力はアプリのログに `[collector-worker <pid>]` という印付きで混ざります。プラグイン 1 つにつき 1 プロセスなので、pid で区別できます。もっと詳しく見たいときは、サーバー側で `VEA_COLLECTOR_WORKER_LOG_LEVEL=DEBUG` を設定します（アプリ全体のログレベルは変えずに済みます）。

### 8.3 よくある失敗

| 表示 | 意味 | 対処 |
|---|---|---|
| `ModuleNotFoundError: No module named '...'` | プラグインが必要とする別のライブラリが入っていない | アップロードによる導入は依存を解決しません。依存を同梱したパッケージを作者に作り直してもらうか、インデックス経由の導入を許可します |
| `load failed: ...` | パッケージの読み込みに失敗 | アプリのログにトレースバックが出ています |
| `TimeoutError: collector execution failed` | タイムアウト超過でワーカーを強制終了した | **タイムアウト（秒）** と **実行間隔（秒）** を見直します。次回の実行で自動的に作り直されます |
| `BatchValidationError: ...` | 取り込もうとしたデータが検証で拒否された。違反した規則がそのまま表示される | プラグイン側の修正が必要です。拒否はまとめて起こり、一部だけ保存されることはありません |
| 提供元が **設定のみ** / `configured plugin is not installed` | 設定に書かれたプラグイン ID に対応する配布物が入っていない | ID の綴りと、インストール済みの一覧を確認します |

詳細な仕様は [コレクタプラグイン（設定リファレンス）](../collector-plugins.md) にあります。

## 9. よくある質問

### 有効にしたのにデータが来ない

**変更を反映**を押しましたか。設定の **保存** はデータベースに書くだけで、稼働中の構成には適用されません。**レジストリ世代**が増えていれば適用済みです。反映後も、最初の実行までは最大で実行間隔ぶんの時間がかかります。

### コンテナを入れ替えたらインストール済みプラグインが消えた

`VEA_PLUGIN_DIR`（既定 `data/plugins`）が永続ボリュームになっていません。サーバー管理者に割り当てを依頼してください。

### 実行状況の「直近成功時の追加件数」が 0 のまま

状態が **成功** なら、プラグインは正常に動いていて取得対象が無いだけです。プラグイン固有の設定（対象の絞り込みなど）を、そのプラグインのドキュメントで確認してください。

### 組み込みコレクタを無効にしてもよいか

できますが、`builtin.vcenter.events` を無効にすると vCenter イベントの取り込みが止まり、イベント一覧・スコア・アラート・ダイジェストのすべてが更新されなくなります。通常は有効のままにしてください。

### 画面にプラグインの設定値が出てこない

プラグイン固有の設定値と機密値は、意図的に一切表示していません。必要な項目は、そのプラグインのドキュメントを参照してください。

### 同じプラグインの新しいバージョンに入れ替えたい

新しいパッケージをアップロードし、**変更を反映**します。実行状況の **使用バージョン** が新しい値に変われば入れ替わっています。
