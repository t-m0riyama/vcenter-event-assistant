# ログのパターン集約の仕組み

リモートログ収集で取り込んだログ（ESXi の vmkernel・hostd・vpxa、vCenter の vpxd）の各行に、数値や ID を伏せた「型」を付けます。型ごとの件数はログタブの「型ごと」の表に表示し、この環境で初めて warning 以上の重大度で出た型はタイムラインのハイライトに表示します。同じ内容で数値だけが異なる大量の行をまとめ、障害の調査で「いつもと違うログが出ていないか」を確認しやすくすることが目的です。

## 1. 型を使う理由

リモートログは、1 時間に数千行になることがあります。同じ処理のログでも、時刻・プロセス番号・タスクの番号・装置の名前などが行ごとに異なるため、一覧では別々の行として並びます。その結果、珍しい行が大量の行に埋もれ、文字列の検索で見つけるにも、何を検索すればよいかを先に知っている必要がありました。

型は、行ごとに異なる値を伏せた文字列です。たとえば、次の 2 行は同じ型になります。

- `cpu12:2097612)NMP: nmp_ThrottleLogForDevice:3893: Cmd 0x2a ... to dev "naa.600508b1001c4d5e" ...`
- `cpu3:2097152)NMP: nmp_ThrottleLogForDevice:3893: Cmd 0x2a ... to dev "naa.600508b1001c9a7b" ...`

どちらも、型は `cpu<N>:<N>)NMP: nmp_ThrottleLogForDevice:<N>: Cmd 0x2a ... to dev "<DEV>" ...` です。

## 2. 型は決めた規則で作ります

型は、本体に組み込んだ正規表現の規則で作ります。自動のクラスタリングは使いません。同じ行からは、取り込みの順序や時期に関係なく、常に同じ型ができます。そのため、なぜその型になったかを規則で説明できます。

### 型を作る手順

1. ログの 1 行目だけを使います。複数行の記録の 2 行目以降（スタックトレースなど）は、型を細かく分けすぎるため使いません。
2. 1 行目を 2,000 文字で切り、先頭の時刻を取り除きます。
3. 次の表の順に値を伏せます。一度伏せた部分は、後の規則では変更しません。
4. 連続する空白を 1 つにまとめ、500 文字で切ります。

| 伏せる値 | 置き換え |
|---|---|
| hostd・vpxa・vpxd の `[Originator@…]` の中の `opID=`・`user=` など | `sub=` の値だけを残します（値の中のパスは伏せます） |
| パスワード・トークン・セッション・Cookie・認証ヘッダーなどの値 | `<SECRET>` |
| `opID=`・`user=` の値 | `<ID>`・`<USER>` |
| URL | `<URL>` |
| WWN・MAC アドレス | `<WWN>`・`<MAC>` |
| IP アドレス（ポート番号を含む） | `<IP>` |
| ファイルのパスと、データストアのパス（`[データストア名] …/….vmx` など） | `<PATH>` |
| 本文中の日付と時刻 | `<TIME>` |
| UUID と VMFS の UUID | `<UUID>` |
| ストレージの装置の名前（`naa.`・`eui.`・`t10.`・`mpx.`）と HBA のパス | `<DEV>`・`<HBAPATH>` |
| 3 桁以上の `0x` の値と、長い 16 進の値 | `<HEX>` |
| 数（語の中の数を含みます。`cpu12` は `cpu<N>`、`esx-01` は `esx-<N>` になります） | `<N>` |

規則の正確な定義は、計画書の 2 章に記載しています。

### 伏せない値

次の値は、意図して伏せていません。

- **2 桁以下の `0x` の値:** SCSI の状態（`H:0x0 D:0x2 P:0x0`）やセンスデータ（`0x6 0x29 0x0`）は、調査で最も重要な違いを示すため残します。状態が異なる行は、別の型になります。
- **名前:** VM 名・ホスト名・データストア名は伏せません。名前を伏せる規則は誤りが多く、型の意味が読み取れなくなるためです。ただし、名前の中の数は伏せます。

### 型のキーと版

型ごとに、ログの種類と型の文字列から作ったキー（32 文字の 16 進）を付け、ログの行に保存します。同じ型でも、ログの種類が異なれば別のキーになります。

伏せ方の規則を変更するときは、規則の版を上げます。版が変わると、同じ行でもキーが変わります。

## 3. 型の台帳に、初めて見た時刻を残します

型ごとの情報は、vCenter ごとの「型の台帳」に保存します。台帳には、生のログは保存せず、型の文字列と次の項目だけを保存します。

- 初めて見た時刻と、最後に見た時刻
- これまでに見た行数
- これまでに見た最も重い重大度
- warning 以上の行を初めて見た時刻と、その行の出どころ

ログは既定で 7 日間しか保存しませんが、台帳は、最後に見た時刻から既定で 90 日間保存します（`LOG_PATTERN_RETENTION_DAYS`）。このため、ログが削除された後も、「この環境で以前に出たことがある型か」を判定できます。`LOG_PATTERN_RETENTION_DAYS` を 0 にすると、期間による削除を行いません。

名前を伏せないため、VM ごとに型が分かれ、台帳の行が増え続けることがあります。1 つの vCenter の台帳が `LOG_PATTERN_MAX_PER_VCENTER`（既定 20,000 行）を超えた場合は、最後に見た時刻が古い型から削除します。ただし、ログが残っている型は削除しません。このため、台帳の行数が `LOG_PATTERN_MAX_PER_VCENTER` を超えたままになることがあります。

## 4. 初めて warning 以上で出た型を判定します

タイムラインのハイライトの「初めて警告以上で出たログの型」のカードには、この環境で初めて warning 以上の重大度で出た型を表示します。以前は info の重大度だけで出ていた型が、表示期間に初めて warning 以上で出た場合も含みます。

重大度は、ログの重大度の語から次のように判定します。warning 以上とは、warning・error・critical の 3 段階です。

| 段階 | 語 |
|---|---|
| critical | `critical`・`crit`・`fatal`・`panic`・`alert`・`emerg` |
| error | `error`・`err` |
| warning | `warning`・`warn` |

表にない語の行と、重大度がない行は、info として扱います。ログタブの型ごとの表でも、最も重い重大度は info と表示します。

### 判定の手順

1. 台帳から、warning 以上の行を初めて見た時刻が表示期間に含まれる型を選びます。起点では区切りません。
2. 型付けに失敗した行の型（`<UNPARSED>`）は除きます。選んだ型について、表示期間の warning 以上の行をログから数えます。vCenter と対象の名前による絞り込みは、タイムラインのログの一覧と同じように適用します。行が 0 件の型は除きます。
3. 最も重い重大度が高い順、最初の時刻が早い順に並べ、最大 10 件を表示します。

カードの各項目には、型、ログの種類、ホスト、vCenter、行数、最初の時刻、重大度を表示します。**ここを起点にする** を押すと、その型の最初の時刻を起点にします。**ログで開く** を押すと、その型と表示期間で絞り込んだログタブを開きます。

### 判定を控える期間

台帳を作り始めた直後は、どの型も「初めて」に見えます。このため、次の条件をすべて満たすまでは判定しません。

- **既存のログへの型付けが完了していること:** 導入の時点で保存されていたログには、順に型を付けます（5 章）。完了するまでは、カードに「ログの型を埋め戻し中のため判定していません」と表示します。
- **慣らしの期間を過ぎていること:** 出どころ（接続先 ID とログの種類の組）ごとに、台帳を作り始めた時刻を記録します。型ごとに、warning 以上の行を初めて出した出どころの開始時刻から `LOG_PATTERN_WARMUP_DAYS`（既定 3 日）が過ぎているかを判定します。ESXi ホストを追加した場合も、そのホストのログは 3 日間判定しません。
  - 慣らしの期間中に初めて warning 以上で出た型は、期間が過ぎた後も「初めて」として扱いません。
  - 開始時刻の記録がない出どころは、慣らしの期間中として扱います。カードには「慣らしの開始時刻の記録なし」と表示します。
  - カードには、表示期間と絞り込みに合うログがある出どころのうち、慣らしの期間中のものを最大 20 件表示します。

表示期間の始まりがログの保存期間より前の場合は、ログが削除された型がカードに表示されないことがあります。その場合は、カードに注記を表示します。

この機能より前に保存したスナップショットの結果では判定していないため、カードに「判定していません」と表示します。表示する種別にログを含めていない場合は、カードを表示しません。

## 5. 既存のログへの型付け

導入の時点で保存されているログ（最大 7 日分）には、定期ジョブ（`log_pattern_backfill`、5 分間隔）が順に型を付けます。1 回の実行で最大 50,000 行を処理します。605 万行の環境では、完了まで約 10 時間かかります。完了するまでの間、ログタブの型ごとの表では、型が付いていない行を「型の計算待ち」として件数だけ表示します。

型付けが完了した後も、このジョブは 5 分ごとに、前回の実行以降に保存されたログに型が付いているかを確認します。新しいバージョンと古いバージョンのアプリが同時に動いている間に、古いバージョンが型のないログを保存した場合に備えるためです。

## 6. ログタブの型ごとの表

ログタブで「型ごと」を選ぶと、指定した期間と条件に合うログを型ごとに集計し、行数の多い順に最大 200 件を表示します。各行に表示する項目は次のとおりです。

- 型とログの種類
- vCenter
- 期間内の行数と、最初と最後の時刻
- 期間内の最も重い重大度
- 台帳で初めて見た時刻

行を押すと、その型で絞り込んだログの一覧に移ります。

集計には期間の指定が必要です。条件に合うログが `LOG_PATTERN_SCAN_MAX_ROWS`（既定 500,000 行）を超える場合は集計せず、期間を短くするか条件を追加するよう案内します。PostgreSQL 16、605 万行の環境で計測した集計の時間は、12 時間分（約 43 万行）で 0.6〜1.1 秒でした。計測の詳細は、運用ガイドの 2.7 節に記載しています。

## 7. 型が表示・保存される場所

型には、伏せていないログの語（VM 名・ホスト名・データストア名など）が残ります。型が表示・保存される場所は次のとおりです。

- **画面:** ログタブの型ごとの表と、タイムラインのカードに表示します。ログと同じく、閲覧の権限（viewer）を持つ利用者も見られます。
- **型の台帳:** ログの保存期間（既定 7 日）を過ぎても、既定で 90 日間保存します。期間は `LOG_PATTERN_RETENTION_DAYS` で短くできます。
- **調査資料の出力:** Markdown の報告書と、ZIP に含まれる結果の JSON に含まれます。資料を外部に渡す前に、内容を確認してください。
- **保存したスナップショット:** 手動で保存したスナップショットの結果にも含まれます。台帳の保存期間とは関係なく、スナップショットの保存期間（既定で 90 日）のあいだは残ります。
- **チャット（LLM）:** 自動では渡しません。ただし、出力した報告書をチャットに添付すると、型も渡ります。

パスワードやトークンなどの値は伏せますが、規則に当てはまらない書き方の秘密の値は残ることがあります。

## 8. 制約と注意事項

- **伏せ方の規則は完全ではありません。** 同じ内容の行が別の型に分かれたり、異なる内容の行が同じ型にまとまったりすることがあります。型はログの要約であり、ログの代わりにはなりません。判断の根拠には、型で絞り込んだログの本文を確認してください。
- **名前によって型が分かれます。** VM 名やデータストア名を伏せないため、同じ内容のログでも VM ごとに別の型になります。空白を含むデータストアのパスも、パスとして伏せられません。また、8 桁未満の短い 16 進の値（スレッド ID など）は一部だけが伏せられ、値ごとに型が分かれることがあります。
- **重大度は、ログの語から読み取ります。** リモートログ収集は、`info`・`warning`・`error` などの語から重大度を読み取ります。ESXi 7 以降の `In(166)`・`Wa(164)` のような形式には対応していません。本文に該当する語がない行は重大度が判定されず、warning 以上の型として扱われないことがあります。
- **規則の版を上げると、台帳の記録は失われます。** 版を上げると、古い版の台帳を削除し、保存されているログ（最大 7 日分）から型を付け直します。7 日より前の記録は失われ、慣らしの期間もやり直しになります。
- **実際のログでの確認は、vpxd のログだけです。** 開発環境の vpxd のログ 112 万行では、228 個の型にまとまりました。慣らしの期間の後に初めて warning 以上で出た型は、1 日に 0〜1 個でした。ESXi のログ（vmkernel・hostd・vpxa）での確認は行っていません。
